# 마포한끼 — 지도에서 식탁까지

마포농수산물시장의 상인 팀 공동 메뉴를 가족 조건에 맞춰 AI로 구성하고, 실제 시장 위성지도 위 공동 픽업대에서 한 번에 받는 모바일 웹 시제품입니다.

**점포 배치·원안·가격·재고는 가상 시연 데이터입니다. 실제 결제·식품 준비·송금·배송은 발생하지 않습니다.** 시장 지도는 실제 Google 위성지도(서울 마포구 월드컵로 235)이며, 그 위의 점포 위치만 가상 배치입니다. 사진 옆 AI 생성 예시 배지는 표시하지 않으며, 이미지 생성 기록은 소스 manifest에 남깁니다.

## 메뉴 순서와 체험 흐름

상단·모바일 하단 메뉴는 `lib/navigation.ts` 한 곳에서 정의하며, 첫 화면은 **AI 한 끼**입니다.

1. **AI 한 끼:** 인원·끼니·간과 풍미 취향·보유 재료/양·추가·제외·대체·기타 8개 자유 입력과 예산·조리시간 2개 스크롤 선택을 읽고 상인 원안과 변경 구성을 비교합니다.
2. **공동 메뉴 9종:** 채소·수산·정육 메뉴와 각 메뉴를 만든 **상인 팀**, 참여 점포를 확인합니다. 메뉴별 음식 사진은 각각 생성한 AI 예시입니다.
3. **시장 지도:** 마포농수산물시장의 **실제 Google 위성지도** 위, 시장 건물 한가운데에 **공동 픽업대**가 있고 18개 가상 점포가 내부에 흩어져 배치됩니다. 점포를 누르면 공급 재료·공동 메뉴(팀 표시)·점포 QR이 열리고, 선택한 점포와 픽업대의 연결선이 표시됩니다. 픽업대를 누르면 주문·픽업으로 이동합니다.
4. **주문·픽업:** 장바구니의 구매 재료·준비비·추가 재료 금액을 확인해 시장 중심 공동 픽업대로 시연 예약합니다. 상인 화면에서 준비 시작→점포 준비 완료를 누르고, 모든 참여 점포가 완료하면 수령을 확인합니다. 수령 후 점포별 밀키트 재료·준비비·현장 추가 금액을 확인해 시연 정산을 확정합니다.
5. **추가 장보기:** 현장에서 실물을 보고 재료를 더 담으면 선택한 주문과 공급 점포 매출에 반영됩니다. 수령 전 추가 품목은 점포 준비를 다시 요구합니다.

QR의 `?shop=`(시장 지도), `?menu=`(AI 한 끼), `?ingredient=`(추가 장보기), `?order=`(주문·픽업)가 각 화면으로 바로 연결됩니다. `source`로 최초 안내 점포를 기록하여 점포 간 구매 연결을 추적합니다. 주문 링크는 같은 브라우저 체험 데이터 또는 같은 서버 저장소에서 열립니다.

## 확대·이동 가능한 시장 지도

- Google 위성지도를 사용합니다. Maps 브라우저 키가 없으면 Google 임베드의 중심·확대 수준과 점포 오버레이를 함께 변경하는 휠·트랙패드, 드래그, 두 손가락 핀치·이동 방식입니다. 변경 시 임베드가 새로 로드됩니다. `VITE_GOOGLE_MAPS_API_KEY`를 설정하면 Google Maps JavaScript API와 지리 좌표 오버레이를 사용합니다. 네이티브 지도 경로는 키가 없어 이번 화면 검증에서 제외했습니다.
- 주 건물 외곽은 [OpenStreetMap way38170384](https://www.openstreetmap.org/way/38170384) 좌표를 사용합니다. 가상 점포 18곳을 서로 다른 간격·블록 크기·각도로 비정형 배치했습니다. 회전된 블록 모서리까지 건물 외곽 안에 있는지 검사합니다. 실제 입점 점포의 위치나 실내 통로를 조사한 지도는 아닙니다.
- 점포 블록과 마커는 위도·경도에 고정되며 지도와 함께 이동합니다. 선택 점포가 화면 밖이면 자동으로 화면 안에 들어옵니다. `시장 전체` 버튼으로 건물 전체 화면을 복원합니다.
- 점포 ID와 좌표, 블록 영역을 분리해 관리합니다. 추후 실제 실내 통로·출입구를 조사하여 길찾기 노드와 연결할 수 있습니다. 현재 점선은 픽업대와의 연결 표시이며 실제 보행 경로가 아닙니다.
- Google·네이버·카카오 외부 길찾기 링크는 시장 주소로 연결합니다. 서버용 Gemini 키는 지도에 전달하지 않습니다.

## Gemini와 서버의 역할

서버의 실제 AI는 **Gemini 3.1 Flash-Lite** 네이티브 `generateContent` API를 사용합니다. `GEMINI_MODEL`로 모델을 변경할 수 있습니다. 등록된 원안·재료·대체 규칙으로 요청마다 JSON Schema를 생성하고 `responseMimeType: application/json` 및 `responseJsonSchema`를 지정합니다.

Gemini는 고객 요청을 `intent` JSON으로 해석합니다. 인원·예산·시간·도구·맛과 재료 변경에는 `evidence`(입력 원문 인용)와 `reason`(해석 이유)이 붙습니다. 서버가 인용의 존재와 허용된 변경 범위를 검사하고, 분량·가격·재고·주문 허용을 계산합니다. **인용 검사는 의미 해석의 완전한 정확성을 보증하지 않습니다.**

미해결 요청은 `not_registered`, `no_rule`, `health_claim`, `ambiguous`로 분류합니다. Gemini 안전 차단·출력 잘림·일일/결제 한도·일시 요청 한도·형식 오류를 구분하며 실패를 성공으로 표시하지 않습니다. 원안 직접 선택은 입력 조건이 적용되지 않는다는 확인을 거칩니다. 알레르기·건강 요청은 원안 구매로 우회하지 못합니다.

주문 시 저장된 원안 버전과 구성을 다시 검증합니다. 중복 예약·품절·변경된 가격을 차단하고 브라우저 가격을 신뢰하지 않습니다. 점포 준비·수령·추가 구매·정산은 `lib/order-workflow.ts`의 동일 계산 함수를 공개 체험판과 서버에서 사용합니다.

## 공개 체험판과 실제 AI

[GitHub Pages 체험판](https://lkjh098-cell.github.io/traditional-market-ai-contest/)은 **외부 AI 호출 없이 규칙으로 작동**합니다. 모든 기능은 해당 브라우저 저장소에 저장됩니다. 다른 기기에서 스캔하면 점포·공동 메뉴 안내를 볼 수 있지만 주문 데이터는 공유되지 않습니다.

Gemini 키는 서버의 `GEMINI_API_KEY` 또는 `GOOGLE_API_KEY`로만 읽습니다. 브라우저·GitHub·QR에 Gemini 키를 넣지 않습니다. (지도용 `VITE_GOOGLE_MAPS_API_KEY`는 별개의 공개 브라우저 키이며 위 리퍼러 제한이 필수입니다.) 2026-10-06 실제 Gemini 3.1 Flash-Lite 호출 5개 사례가 모두 검증을 통과했습니다. 보유 재료·추가 구매, 등록 대체, 모호한 분량·도구, 알레르기·건강 요청, 미등록 재료·인용 예시를 확인했습니다. 로컬 서버의 /api/adapt에서도 실제 호출로 19,000원 구성을 확인했습니다. 자동 테스트 76개가 통과했습니다. 이 검증은 고정 사례의 결과이며 모든 표현의 정확성을 보증하지 않습니다.

## 실제 Gemini 검증 재실행

`.env.local`에 서버용 키를 저장한 후 `node scripts/verify-gemini-live.mjs`를 실행합니다. 실제 API 호출이 발생합니다. 보고서는 기본적으로 Git에서 제외된 `.local-data/gemini-live/report.json`에 저장됩니다.

첫 실제 호출에서 전체 JSON Schema의 큰 배열 상한으로 HTTP400이 발생했습니다. wire schema의 `maxItems`를 제거하고 서버 Zod의 배열 길이 제한과 등록 ID enum 검증은 유지했습니다. nullable 원안 ID는 string enum과 null의 `anyOf`로 표현합니다. 미입력 맛을 false로 채우지 않도록 스키마 설명과 프롬프트를 보강했습니다.

## 실행

Node.js24 이상을 권장합니다. GitHub에는 전체 소스와 `docs/` 체험판을 함께 보관합니다.

```sh
npm install
cp .env.example .env.local
# 실제 Gemini 사용 시 .env.local에 GEMINI_API_KEY를 로컬에서 설정
# (선택) Maps JavaScript API 위성지도: VITE_GOOGLE_MAPS_API_KEY — 리퍼러 제한 키만
npm run build:pages
npm run dev:local
```

빠른 로컬 서버는 `http://127.0.0.1:5173/`에서 같은 화면과 실제 API를 제공합니다. SQLite에 시연 자료를 저장하고 기존 D1 API와 동일한 경로를 사용합니다. 기본 접속은 이 컴퓨터에서만 허용합니다. `.local-data/`와 `.env.local`은 Git에서 제외합니다.

Cloudflare Workers/D1 배포용 구현도 유지합니다.

```sh
npm run build
npm run db:local
npm run dev
```

```sh
npm test
npm run typecheck
npm run test:flows
```

`npm test`는 AI 해석·주문 흐름·메뉴 9종·지도/메뉴 순서(`tests/map.test.mjs`: 메뉴 순서, 픽업대=시장 중심, 투영 정확도, 화면 안 마커 배치, 위성 URL, 키 노출 범위)를 검사합니다. `test:flows`는 로컬 서버에서 시연 예약·준비·수령·추가 구매·정산을 생성해 검사합니다. 실운영 데이터에 실행하지 마세요. 테스트는 실제 결제를 하지 않습니다.

## 예산·시간 선택과 가까운 대안 (2026-10-06)

- 한 끼 예산·조리시간은 직접 입력 대신 스크롤 선택창을 사용합니다. 기본 선택은 상관없음입니다. 기존 예시 문자열과 동의 후 추가된 세부 금액도 표시합니다.
- Gemini 해석 후 서버가 동일 인원·재료 조건으로 등록 메뉴를 비교합니다. 예산 안의 다른 메뉴와 예산의 20%(최대 5,000원), 원안 시간 최대 10분까지 초과하는 대안을 함께 보여 줍니다. 재료·도구·알레르기·건강 요청과 재고 검증은 유지합니다.
- 대안에는 주문 가능한 plan ID가 없습니다. 초과 금액·시간과 변경될 상한을 확인한 뒤 전체 입력으로 다시 해석·계산합니다. 기존 조건의 주문은 계속 차단됩니다. 입력 중 조건이 바뀌면 이전 요청의 응답은 표시하지 않습니다.
- 네트워크·타임아웃·500/502/503/504 오류에만 짧은 지연 후 한 번 재시도합니다. 사용 한도·권한·안전 차단은 자동 재시도하지 않습니다. [Gemini 오류 대응 안내](https://ai.google.dev/gemini-api/docs/troubleshooting)를 참고했습니다.
- 자동 테스트 76개와 UI 관련 타입 검사가 통과했습니다. 실제 로컬 Gemini 호출에서 15,000원·15분 두부전골 요청은 3,000원·5분 초과 대안으로 표시되었고, 변경 확인 후 18,000원·20분 구성 및 주문 가능 상태를 확인했습니다. 비교·동의·구성만 확인했으며 실제 주문은 하지 않았습니다.
- 사용자가 첨부한 과거 연결 실패는 이번 진단에서 재현되지 않아 당시 원인은 확정하지 못했습니다. 오류 설명과 일시 장애 재시도를 보강했습니다.

- 터치 화면: 두 손가락의 거리와 중심 이동으로 확대·축소 및 이동합니다. 점포 위에서도 드래그할 수 있고 짧은 탭만 점포 선택으로 처리합니다.
- 화면에는 `시장 전체` 복귀 버튼만 남겼습니다. 키보드 방향키·+/−·Home 조작은 유지합니다.
- Google 위성 임베드와 점포 레이어에 같은 좌표 변환을 적용하고, 새 영상 로딩 중에는 이전 영상과 레이어를 함께 보여 줍니다. 임베드는 제스처 종료 후 정수 확대 단계로 맞춥니다. 큰 이동·축소 시 새 영상 로딩 전 지도 가장자리에 배경이 잠시 보일 수 있습니다.
- 공개 브라우저 키가 설정된 Google Maps SDK 모드는 SDK의 기본 제스처를 사용합니다. 휴대폰 실기기 핀치 및 인증된 SDK 모드는 별도 확인이 필요합니다.


## 예산·시간 범위와 간·풍미 주문

- 예산과 조리시간은 구간으로 선택합니다(예: 10,000~20,000원, 10~20분). 서버는 윗값을 상한으로 적용하며 더 저렴하거나 빠른 메뉴도 허용합니다. 이전에 저장한 단일 상한과 초과 대안 동의값도 유지합니다.
- 마늘 많이·조금은 상인 등록 풍미 규칙을 이용해 2인 기준 각각 다진 마늘 20g·10g을 추가합니다. 추가금은 각각 800원·400원의 가상 시연 가격입니다. 인원이 바뀌면 분량·금액도 조정됩니다.
- 간 담백하게·진하게는 등록된 소스·육수량을 75%·125%로 구성합니다. 변경량과 가격을 고객에게 보여 주고 공급 점포의 실제 준비 목록에 반영합니다.
- 적용 가능한 구성의 주문 버튼은 주문서를 바로 엽니다. 미등록·서로 충돌하는 요청은 수정할 위치로 안내하며 주문 가능한 변경을 상인 수동 확인으로 보류하지 않습니다.
